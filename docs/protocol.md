# Wisp protocol v1

Local IPC is newline-delimited JSON on `$XDG_RUNTIME_DIR/wisp/wispd.sock`.

### Chat workspace commands

- `set_conversation_tab`: `{conversation_id, closed}` persists only that user's tab visibility.
- `clear_chat_history`: `{conversation_id,for_everyone:false}` hides prior history for that user; two DM participants clearing removes their common cleared prefix from storage. Explicit `for_everyone:true` requires a room owner/admin and deletes room history for all members. The UI requires confirmation, including an irreversible/all-users warning for rooms. Cached images are purged.
- `create_room`: `{name}` creates a private persistent room with the creator as owner; returns a conversation without joining a call.
- `invite_to_room`: `{conversation_id,user_id}` adds a circle friend as a member; caller must be owner/admin. Never autojoins a call.
- `set_room_admin`: `{conversation_id,user_id,admin}` grants/revokes a member's admin role; only the room owner may call it. Owners cannot be demoted.
- `paste_clipboard`: explicitly reads the local clipboard and returns `{token, url}` for a staged PNG, or `{text}`. It does not upload anything.
- `discard_image_draft`: `{token}` removes a staged local image.
- `send_image_message`: `{conversation_id, token, caption}` uploads the staged PNG and commits a message. The token is generated by the daemon; callers cannot supply an arbitrary file path.
- `load_chat_image`: `{message_id}` fetches an authenticated image into the local cache and returns `{message_id, url}`.
- `import_chat_files`: `{urls: ["file:///…"]}` stages up to eight local regular files atomically. Returns `{attachments:[{token,url,file_name,size,is_image}]}`. Raster images are normalized to PNG; generic files remain inert bytes. No upload occurs.
- `discard_attachment_draft`: `{token}` removes a staged image or file (`discard_image_draft` remains an alias).
- `send_attachment_message`: `{conversation_id,token,caption,keep:false}` sends a staged attachment and discards it after server acknowledgement. Files stream from an open descriptor in bounded chunks, resuming by draft token. The UI sends batches sequentially and keeps unacknowledged drafts.
- `set_file_retention`: `{message_id,keep}` exempts a visible file from automatic expiry, or restores its original deadline. Any member with visible history can change this flag. Expired files cannot be restored.
- `save_chat_file`: `{message_id}` explicitly downloads a visible file message into a unique Downloads/Wisp directory, without overwriting or executing files; returns `{message_id,url,directory_url}`.
- `edit_message`: `{message_id, text}` edits your own text or image caption via `PATCH /v1/messages/{id}`. Messages expose nullable `edited_at`; edits retain `created_at` and emit `message_updated`, not a new-message notification.
- `delete_message`: `{message_id}` removes your own message for everyone via `DELETE /v1/messages/{id}`, including its image blob, and emits `message_deleted`.

Image messages have `content_type: "image/png"` and a payload containing only
`width`, `height`, and `caption`. Bytes are stored separately, not in snapshots.
The host exposes `POST /v1/messages/image` with `{conversation_id, png_base64,
caption}`, and `GET /v1/messages/{id}/image` with the same bearer authentication
as other endpoints. Cleared history and non-members cannot access image bytes.
Images are limited to 12 MB, 32 megapixels, and 16384 pixels on either axis.
`POST /v1/messages/file` accepts `{conversation_id,file_name,data_base64,caption}`;
`GET /v1/messages/{id}/file` enforces the same membership/history checks as images.
File messages use `application/octet-stream` and metadata `{file_name,size,caption}`,
with bytes stored separately. The legacy JSON endpoint retains its 25 MiB file limit;
current clients use the uncapped chunk protocol below. Filenames
must be 1–200 bytes, without path separators or control characters. Caption edits
and message deletion also apply to files; deletion cascades to attachment storage.
`POST /v1/conversations/tab` accepts `{conversation_id, closed}` and
`POST /v1/conversations/clear` accepts `{conversation_id,for_everyone:false}`.
The default is intentionally personal so older clients cannot silently clear a
whole room. Mutual DM clearing deletes only messages at or before both users'
cutoffs. Room-wide clearing requires owner/admin authority and removes messages
and attachments regardless of Keep flags. New incoming direct messages reopen
the recipient's closed tab. Closing a tab never deletes history.
Conversation snapshots include nullable `history_cleared_at`, allowing clients
to purge cached images when another device clears history. Deletes also remove
cached image files as clients receive the updated snapshot.

### Streaming files and retention

- `POST /v1/file-uploads`: `{id,conversation_id,file_name,size,caption,keep}` creates/resumes an owned upload. The UUID is the daemon draft token. Returns `{received_bytes,next_chunk,message_id}`.
- `PUT /v1/file-uploads/{id}/chunks/{index}`: raw bytes, exactly 4 MiB except the final chunk. Sequential offsets, identical chunk retries, and idempotent completion prevent duplication. This is a per-request bound, not a file-size cap.
- `POST /v1/file-uploads/{id}/complete`: commits one file message once all bytes arrive; retry returns the same message.
- `GET /v1/messages/{id}/file`: authenticated streaming download; deleted, expired, cleared, and non-member files are denied.
- `PATCH /v1/messages/{id}/retention`: `{keep}` updates file retention.

File payloads additionally expose `keep`, nullable `expires_at`, and `expired`.
Expiry is measured from completed upload: <=1,000,000,000 bytes indefinitely;
>1,000,000,000 through 5,000,000,000 bytes 48 hours; larger files 24 hours.
Keep bypasses expiry, not explicit message/history deletion. Unkeeping uses the
original timestamp and can expire the file immediately. Cleanup removes chunks
and leaves the expired message marker; it runs at startup and every minute.
Incomplete uploads expire after 24 hours without activity. SQLite backups include
all chunks. Deletion frees reusable pages, not necessarily filesystem space, and
does not erase old backups. IPC emits `file_transfer_progress` with
`{id,direction,bytes,total}`; transfers do not block room/media commands.

### Persistent rooms

`POST /v1/rooms`, `/v1/rooms/invite`, and `/v1/rooms/admin` match the corresponding
IPC arguments above. Conversation snapshots expose `self_role` (`host`, `admin`,
or `member`), `member_roles` keyed by user ID, and `can_clear_for_everyone`.
New rooms are private, with persistent membership and owner/admin roles. Jared
is Porch's owner, not a global administrator of other users' rooms. All joining
paths enforce membership, including joining via a friend or active call ID.

The socket is mode `0600`. Every client command has a version and request ID:

```json
{"v":1,"id":"a1","type":"command","name":"set_muted","args":{"muted":true}}
```

Results are request-scoped:

```json
{"type":"result","v":1,"id":"a1","ok":true,"value":{"muted":true}}
```

Snapshots are complete and events are ordered by `seq`:

```json
{"type":"event","v":1,"seq":42,"name":"self_state_changed","payload":{"snapshot":{}}}
```

Supported commands are `hello`, `status`, `set_presence`, `join_friend`,
`join_hangout`, `leave`, `set_muted`, `toggle_muted`, `set_deafened`,
`toggle_deafened`, `respond_knock`, `share`, `camera`, `watch_video`,
`refresh_audio_devices`, `set_input_device`, `set_output_device`,
`set_audio_preset`, `refresh_video_devices`, `set_camera_device`,
`set_video_quality`, `set_video_codec`, `set_push_to_talk`,
`set_push_to_talk_shortcut`, `push_to_talk_press`, and
`push_to_talk_release`. M4 adds `open_direct`, `send_direct`, `send_message`,
`mark_conversation_read`, `join_spot`, `create_invite`, `list_devices`, and
`revoke_device`. The legacy `open_surface` and `close_surface` commands
target the first available video publication. Device commands take a stable
device `id`; audio presets are `natural`, `clear`, or `studio`. Repeating
`push_to_talk_press` renews the daemon-owned lease without emitting another
state event. Invalid versions, JSON, or commands return a structured error and
do not terminate the IPC connection.

`respond_knock` takes a `knock_id` and a response of `accept` or `later`.
Pending incoming knocks are included in the snapshot's `knocks` array with the
sender and expiration time. Joining a friend in Knock presence returns a
`knock_sent` result instead of treating the request as an error.

The snapshot's media state includes `remote_audio_participants`,
`remote_muted_participants`, `remote_video_participants`, per-track
`remote_videos`, receive/render counters,
native-surface state, and optional `error_code`/`error` fields. A remote video
publication makes Watch available but remains unsubscribed until requested.
Screen sharing reports the portal's native `source_width`/`source_height`
separately from the encoded `width`/`height`, plus the actual
`encoder_backend` used for the share.
Each remote screen/camera entry reports its target, MIME type, simulcast
capability, subscription, requested layer, dimensions, and frame counters. The
nested `camera` object contains capture devices, selection, publication state,
dimensions, and recoverable errors. The nested `video` object contains the
publishing quality, codec, discovered encoder backends, and whether hardware
acceleration is actually active. Error codes are stable machine-readable
categories; `error` remains suitable for direct display. The nested `audio`
object contains input/output inventories, selected device IDs, the processing
preset, and an integer `input_level` from 0–100. While a call is active, `wispd`
detects device changes, switches to an available fallback, and restores the
preferred device if it returns.

The self state contains `push_to_talk.enabled`, `push_to_talk.active`, the
optional global `shortcut`, its `shortcut_backend`, and any descriptions in
`shortcut_replaced`. `set_push_to_talk_shortcut` accepts a normalized shortcut
string or `null` to clear it. Omarchy/Hyprland configuration is generated and
validated by `wispd`, never by the presentation layer.
Manual `muted` state always takes precedence. A PTT press expires after 30
seconds unless renewed and is also released on room changes or media reconnect.
`media.active_speakers` contains sorted participant display names from LiveKit.

Snapshots also contain authorized `conversations`, recent `messages`, saved
`spots`, the current user's `devices`, and an optional newly created
`last_invite`. Conversation summaries include type, members, latest message,
unread count, and an optional `spot_id`. A Spot-backed conversation is durable
even though each associated media room is ephemeral. Presentation clients
still receive complete snapshots rather than maintaining a second local
message database.

The server control API uses invite-enrolled device credentials to mint 12-hour
sessions. Every authenticated HTTP and WebSocket request carries its session as
`Authorization: Bearer …`; query-string tokens remain only for explicitly
enabled local development sessions. Registration and session requests include
the protocol version and mismatches are rejected before state is changed.
Credentials and media keys never enter Quickshell.

Server event frames contain change metadata only. Text content is returned by
authorized snapshot/message endpoints, and the server commits each message
before acknowledging it. Normal logs include neither message payloads nor
device, session, invite, or E2EE secrets.
