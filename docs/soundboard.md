# Server soundboards

Open **Soundboard ▾** beside the main microphone controls to play sounds. The
menu follows your voice server during a call, or the selected server outside a
call. Click a sound's name to play into voice; Preview, volume and Stop remain
available. **Manage sounds** opens uploads and removal; **Back to sounds** returns
to playback. The Soundboard button in call controls opens the same menu.

**Settings → Soundboard** also opens the selected server's full library.

The bundled starter pack contains eight original synthesized effects: Ping,
Applause, Air Horn, Rimshot, Drum Roll, Sad Trombone, Level Up, and Boing. Select
**Add starter sounds** in an empty menu or Manage sounds to add them to that
server. Matching names are skipped, existing uploads are preserved, and adding
sounds never plays them. Deleted starters can be restored with the same button.
The pack's WAV files are generated by `python3 scripts/generate-soundboard.py`;
no external recordings or samples are used. Files are loaded only when adding
them to a server, and share the same upload/removal rules as other sounds.

Every server has an independent library of up to 64 sounds. Members can upload
WAV, MP3, Ogg and FLAC clips (up to 10 seconds, input files up to 20 MB). Give the
sound a name and select Upload. Names must be unique on that server. The uploader
can remove their own sounds; server owners and administrators can remove any sound.
Removal requires confirmation. Upload errors preserve the chosen file and name.

**Preview** plays through the selected speaker. During a call, mute the microphone
first to keep the preview private. **Play into voice** requires an unmuted,
undeafened call on the sound's server. It uses the existing voice track, so listeners
don't need a new client to hear sounds. New sounds replace the previous sound;
there is a one-second interval between room playback starts. Volume affects the
next playback. **Stop** cancels playback, including a pending download. Muting,
deafening, leaving, and voice moderation stop or suppress room playback. Nothing
automatically joins a room.

The client imports using `ffmpeg` on PATH; this is needed for uploading, but not
for playback. It decodes a local copy with external protocols disabled, a 15-second
timeout, and a bounded duration. The server accepts only validated mono 48 kHz,
16-bit PCM WAV data. Each stored sound is at most 960,044 bytes. Audio is fetched
only on explicit playback; QML holds metadata, not audio blobs. The call popup
creates its contents only while open. Server library files are stored on that
server and available to its authenticated members; they are not end-to-end encrypted.

Effects enter the microphone stream after speech processing. While an effect
plays, microphone samples use 40% gain and sound samples use at most 55%, leaving
headroom even for full-scale audio. The speech processing itself is unchanged.

Validation:

- `cargo test --release -p wisp-protocol -p wisp-server -p wispd`
- `QT_QPA_PLATFORMTHEME=basic bash scripts/test-soundboard-ui.sh`
- `QT_QPA_PLATFORMTHEME=basic bash scripts/test-streams-and-search.sh`
- `QT_QPA_PLATFORMTHEME=basic bash scripts/test-chat-ui.sh`
- `WISP_TEST_BUILD_PROFILE=release bash scripts/test-audio-test.sh`
- `python3 tests/soundboard-room.py` (after a release build and LiveKit setup)

The audio tests use generated audio, temporary servers/daemons, and private
virtual speakers. They check all four import formats, actual audible preview output,
Stop during pending playback, and room isolation without opening a real microphone
or joining a production voice room. The room test measures the uploaded tone at
another temporary client after LiveKit transport, then checks mute and leave.
